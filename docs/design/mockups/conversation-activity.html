What the agent touched, one click away

A card on the right of a chat lists what the agent has touched in this conversation: the files it changed and where they sit, the page it drove, the board it drew on, the agents it spawned, and every image in the chat. A row appears the first time the agent touches that thing, and opens the pane on that tab. Where the chat is too narrow for the card, it condenses to a pill in the title bar, just the rows' glyphs and an arrow, that drops the same rows down. On the phone the header bar goes: a back button and a pill with the chat's title float over the transcript, and the pill opens the chat's page with the same rows. Press Replay the run to watch the desktop and the phone fill in together.

Phone

The left phone is live: tap the pill, then a row, and use the back arrow. The other two hold one step each, so the whole path is visible at once.

1 · No header bar. A back button and one pill float over the transcript: the runtime's mark, the chat's title, and the glyphs of the newest things the agent touched, in violet while an agent is in one. Tap the pill for the rest.
2 · The chat's page. Its title, project, machine and model, then the desktop card's rows in the same order with the same facts, then Mark unread and Settle, which the ⋯ menu used to hold.
3 · A row opens its screen. Changes and Agents open the screens the phone already has. Files and Library are new. Browser and Canvas show the agent's latest picture of the page or board.

How the card condenses

The rule is about the chat's width, not the window's: a wide window with the pane open has a narrow chat.
  1. Room for it (the chat is at least 860px wide): the card is docked at the top right, always open. The transcript keeps clear of it.
  2. No room (a medium or narrow window, or the pane is open): the card becomes a pill in the title bar holding only the rows' glyphs and an arrow. Clicking it drops the card down under it. A row opens the pane, and the drop-down closes. In a narrow window the folder and branch chips leave the title bar first, so the pill never has to.
  3. Phone: no header bar. A back button and a pill float over the transcript. The pill shows the chat's title and its newest glyphs, and opens the chat's page, where the rows live. Each row opens a screen.

What the rows show

  • Order. Rows appear in the order the agent first touched each thing, and don't reorder later. Files arrives with Changes: one says what changed, the other shows where it sits in the project. Library stays last, because it holds what came out of the run rather than a place the agent worked.
  • A row the agent is in right now has its glyph in the agent-trail violet the pane tabs and Files tree already use. A spawned agent's row uses its agent glyph. No dots.
  • New, not yet opened: the glyph is in primary ink instead of muted. Opening the row clears it.
  • The pill's glyphs follow the same rules, so it says the same thing at a glance.
  • A new Diff glyph, → : plus over minus in the rounded frame the pane's other glyphs share. It replaces DiffGlyph in pane/paneKinds.tsx, so the pane tab changes too.

On the phone

  • Changes opens the Changes screen the phone already has. Today you reach it from the diff pill under the composer, and that pill can stay.
  • Files is a new, read-only tree, opened out to the folders the agent edited, since the phone has no file browser yet.
  • Agents opens the Agents screen that "See agents" opens today.
  • Browser shows the agent's last screenshot of the page. A localhost page on the desktop isn't reachable from the phone, so the screen offers to open it only when the desktop has published that dev server, as Web pages does.
  • Canvas shows the board as the agent last drew it, read-only.
  • Library is new: every image in the chat, with a filter by who added it.

Things to decide

  • Should the phone's floating controls hide while you scroll back through the transcript and come back when you scroll down, or stay put?
  • Does the chat's page want a Notifications switch for this chat?
  • Should the desktop card have a close control, so a person who never wants it docked keeps only the pill?
  • Does the composer's diff pill on the phone stay, now that the header pill carries Changes too?
  • Should Terminal get a row when the agent runs a long command?
